# Формат агента в библиотеке Teamly

Открытый формат Agent Skills (папка со `SKILL.md`), чтобы агент работал в Claude Code, а позже и в Codex. Никакой привязки к платформе.

## Папка

```
<slug>/
  SKILL.md            маршрутизатор, < 500 строк
  ontology.md         онтология задачи (forge/references/ontology-schema.md)
  references/
    rules.md          правила и механизмы, у каждого источник и дата
    examples.md       3–5 хороших «вход → результат» и 1 разобранный плохой
    sources.md        откуда взято каждое знание (URL, чат, файл) с датой
  evals/
    evals.json        5 задач с проверками (forge/references/eval-protocol.md)
  card.json           карточка библиотеки
  CHANGES.md          только у форка: что поменял относительно основы и почему
  scripts/            по необходимости: детерминированные проверки и преобразования
```

## Язык

Библиотека общая для всех стран: инструкции агента (`SKILL.md`, `ontology.md`, `references/`) и поля карточки, которые видит человек (`name`, `role`, `outcome`, `example`, `needsFromYou`, `costFor`, `time`), пишутся **по-английски**. Результат агент выдаёт на языке человека (или на том, что он попросил). Русские тексты карточки можно сохранить в `card.json` → `i18n.ru`.

## Скелет SKILL.md

```markdown
---
name: <slug>
description: <Что делает для кого>. Используй, когда <фразы, файлы, ситуации>. Не для <соседние задачи>.
---

# <Имя>: <роль>

## Цель и «готово»
<1–3 строки. Самое важное вверху: после сжатия контекста от скилла остаются первые ~5000 токенов.>

## Стоп-точки
- <когда остановиться и спросить человека>

## Порядок работы
- [ ] 1. ...  (каждый шаг — конкретное действие; ссылки на механизмы в references/rules.md)

## Проверка перед сдачей
<сверь результат с критериями качества из ontology.md; покажи доказательство; не прошло — исправь и проверь снова>

## Формат результата
<шаблон>

## Справка
- Онтология задачи: ontology.md (читать в начале каждой задачи)
- Правила и пороги: references/rules.md (читать на шаге N)
- Примеры: references/examples.md
- Источники: references/sources.md
```

## card.json

```json
{
  "slug": "trend-radar",
  "name": "Trend Radar",
  "role": "Находит, что залетает в нише за неделю",
  "job": {
    "area": "content",
    "owns": "Knowing what blows up in your niche this week",
    "give": "Your niche and main platform",
    "steps": ["Scans X, Reddit, YouTube, TikTok and Reels for 7 days", "Ranks posts by growth vs the author's usual level", "Breaks down the hook, format and emotion"],
    "get": "10 findings with sources and an idea for each",
    "not": "Writing scripts or posting"
  },
  "author": "Igor Kossolapov",
  "authorKind": "practitioner | teamly | community",
  "version": "1.0.0",
  "upstream": null,
  "tags": ["content", "research", "live-data"],
  "interfaces": ["Publishable"],
  "functionType": "поисковая | учётная | извлекающая | творческая",
  "outcome": "<что получишь, одной строкой>",
  "example": ["<строки примера результата>"],
  "needsFromYou": "<что нужно от человека>",
  "tools": ["WebSearch", "Teamly API: живые данные (через ключ Teamly)"],
  "costPerResult": 0.4,
  "costFor": "<за какие инструменты платятся кредиты>",
  "costBreakdown": [{"name": "Live social data", "providers": ["Instagram", "X", "TikTok"],
                     "tool": "<что именно делает платный вызов>", "unit": "one radar run", "credits": 0.4, "optional": true}],
  "time": "~10 мин",
  "results": 0,
  "evalWin": null,
  "evalDate": null,
  "sources": 0,
  "updatedAt": "2026-10-22"
}
```

`job` — должностная инструкция агента, по ней библиотека рисует карточку. Одна работа на агента: если два агента делают одно и то же, в библиотеке остаётся один (у старого `"replacedBy": "<slug>"`).
- `area` — этаж офиса: `content`, `fundraising`, `planning`, `legal`, `sales`, `hiring`, `product`, `finance`, `support`.
- `owns` — за какой результат отвечает, одна строка до 60 знаков, без глагола «помогает».
- `give` — что даёт человек, до 60 знаков. `get` — что получает, до 70 знаков, с числом, если оно есть.
- `steps` — ровно 3 шага из «Порядка работы» в SKILL.md, по 30–55 знаков, каждый начинается с глагола.
- `not` — чего агент НЕ делает (соседняя работа), чтобы границы были видны.
Пишется по-английски; русский вариант — в `i18n.ru.job`.

`runtime` — где агент может работать: `{"local": true, "cloud": true|false, "os": ["mac", "windows", "linux"] (только если работает не везде), "why": "<почему, одной строкой>"}`. `cloud: false`, если нужны программы или файлы на компьютере человека (монтаж, локальные приложения, локальные MCP); `true`, если хватает интернета, ключа Teamly и файлов в папке команды.

`costBreakdown` — платные инструменты через ключ Teamly, по ним кошелёк в панели показывает, куда уходят Teamly Dollars: `name` — коротко (до 24 знаков), `providers` — сервисы, которые увидит человек (Instagram, X, Seedance…), `unit` — за что цена, `credits` — оценка в долларах (точную называет API), `optional: true` — только по просьбе человека. Нет платных инструментов — пустой список.

`integrations` — к чему агент подключён: `[{"name": "Web search"}, {"name": "Live social data", "optional": true}]`. Библиотека показывает их вместо цены: цену знают только после вызова. Свои скрипты и файлы — не интеграции. Нет поля — панель читает `tools`.

`results` — сколько человек получили результат: его будет считать библиотека Teamly; локально это число из `card.json` как есть (оценки и звёзды панель показывает отдельно, из `~/.teamly/ratings.jsonl`). `evalWin` — «W/T/L против обычного Claude на N задачах», заполняется после доказательства. Агента с пустым `evalWin` библиотека показывает без значка проверки: значок «beats Claude» есть только у прошедших тест.

## Контрольный список перед выпуском

1. Описание: что делает и когда звать, слова-триггеры первыми, «не для …», до 1024 знаков.
2. В агенте только то, чего Claude не знает: «если убрать — Claude ошибётся?».
3. Знания из чатов и материалов человека и ремесла, с источниками. Ничего «из головы».
4. SKILL.md < 500 строк, ссылки на один уровень вглубь, длинные references с оглавлением.
5. Критерии качества проверяемые, «да/нет».
6. 3–5 разобранных примеров и 1 плохой.
7. Объясняет «зачем», а не кричит ВСЕГДА / НИКОГДА.
8. Порядок работы — чеклист с петлёй «проверил → поправил → снова».
9. Самопроверка с доказательством; каждое фактическое утверждение со ссылкой или убрано.
10. Детерминированные и хрупкие шаги — скриптами, сказано: запускать или читать.
11. Стоп-точки: N неудач, необратимое действие, лимит итераций, можно сказать «не знаю».
12. Фиксированный формат результата.
13. Нет противоречий и устаревшего, один термин — одно понятие.
14. Инструменты настоящие: имена MCP полностью, ничего не предполагается установленным, ошибки говорят, как починить.
15. Тесты в `evals/evals.json`, 5 задач, есть задача «не по профилю».
16. В `card.json` есть `job`: `owns`, `give`, 3 `steps`, `get`, `not` совпадают с SKILL.md и не обещают больше, чем агент делает.

## Безопасность (обязательно для библиотеки)

- Никаких инструкций, подгружаемых из интернета на лету («скачай и выполни»).
- Никаких бинарников. Скрипты короткие и читаемые, проверяются перед публикацией.
- Никаких ключей, паролей, личных данных, имён частных людей и приватных путей в агенте, который идёт в общую библиотеку. Личное — только в `config` форка на машине человека.
- Отправка, публикация, оплата, удаление — только с подтверждением человека.
